부족한 점 · 권장 작업 (우선순위순)

  1. High추천/맞춤 기능이 시드 데이터 부족으로 사실상 항상 폴백 상태
    /api/recommendations/trips, /api/recommendations/records, /api/tour/recommended 모두 프론트 연동은 끝났지만, 현재 시드 데이터로는 카테고리·지역 매칭이 거의 발생하지 않아 빈 배열을 반환합니다. 프론트가 이를 인기순/예시 카드로 조용히 감추고 있어 개인화 기능이 실제로 동작하는지 QA로 확인하기 어렵습니다. 백엔드에 태그·지역이 다양하게 채워진 시드 데이터가 필요합니다.
  2. High피드백(참견) 수정·삭제 API가 프론트에 연결되지 않음
    PATCH/DELETE /api/trips/{tripId}/feedback/{feedbackId}가 백엔드에는 있지만 src/api/feed.js에 함수가 없습니다. 사용자가 남긴 참견을 고치거나 지울 수 있는 UI가 전혀 없습니다.
  3. High저장한 여행 목록 조회·삭제 미연동 (마이페이지 부재)
    GET/DELETE /api/saved-trips가 미사용입니다. saveTrip으로 저장은 가능하지만 무엇을 저장했는지 확인하거나 취소할 화면이 없고, Navbar의 /mypage 링크도 라우트가 없어 죽은 링크입니다. 마이페이지(또는 유사 화면) 신설이 필요합니다.
  4. Mid여행 기록(TripRecord) CRUD 전체 미연동
    POST/GET/PATCH/DELETE /api/trips/{tripId}/record 4개 엔드포인트 모두 프론트에 대응하는 api/*.js 모듈이 없습니다. RecordUploadModal.jsx UI는 존재하지만 실제 API 호출 코드가 붙어 있지 않아 사실상 목업입니다.
  5. Mid로그인 상태 비밀번호 변경 미구현
    PATCH /api/auth/password에 대응하는 프론트 화면·함수가 없습니다. 비밀번호 찾기(재설정) 흐름만 구현되어 있습니다.
  6. Mid선호도 수정 화면 부재
    updatePreferences 함수는 src/api/preferences.js에 정의되어 있지만 어디서도 호출되지 않습니다(PUT /api/preferences). 온보딩(등록)만 가능하고 이후 취향을 바꿀 UI가 없습니다.
  7. Mid피드백 추천 장소 → 카트 담기 미연동
    POST /api/trips/{tripId}/feedback/recommendations/{recommendationId}/cart가 미사용입니다. 참견에 달린 추천 장소를 바로 내 카트로 옮기는 기능을 구현할 수 있습니다.
  8. Low관광 콘텐츠 보조 API 4종 미사용
    /api/tour/categories, /api/tour/contents/nearby, /api/tour/festivals, /api/tour/stays가 프론트에 전혀 연결되지 않았습니다. ExploreSection의 탭·필터를 확장할 때 활용할 수 있습니다.
  9. Lowtext/html 응답을 401로 변환하는 인터셉터
    src/api/client.js는 세션 만료 시 백엔드가 로그인 HTML로 리다이렉트하는 상황을 감안해 text/html 응답을 강제로 401 에러로 바꿉니다. 의도된 방어 로직이지만, 로컬 프록시·CORS 설정이 잘못됐을 때도 같은 증상(HTML 응답)이 나올 수 있어 디버깅 시 혼동될 수 있습니다.

백엔드 요청 목록

프론트 관점에서 백엔드 팀에 요청하면 좋을 항목입니다.

  • 추천 매칭용 시드 데이터 확충 — 관광 콘텐츠 카테고리·지역 태그가 다양하게 채워진 시드가 있어야 /api/recommendations/*, /api/tour/recommended를 실제로 검증하고 데모할 수 있습니다.
  • 로컬 개발용 CORS Origin 패턴 확인 — 프론트 로컬 개발 서버(Vite, 기본 5173)에서 쿠키 기반 인증(withCredentials: true)이 원활히 동작하도록 허용 Origin 목록을 다시 확인해 주세요.
  • 좋아요(likeCount) 엔티티 도입 여부 확정 — 현재 saveCount(저장 수)만 내려오고 likeCount는 존재하지 않습니다. 프론트 feedAdapter.js는 이를 감안해 saveCount만 사용 중이며, 별도 좋아요 기능이 예정이라면 API 스펙을 알려주시기 바랍니다.
  • 피드백 수정·삭제, 저장한 여행 목록/삭제 API의 프론트 연동 일정 조율 — 백엔드는 이미 구현되어 있으므로 프론트 작업 일정에 맞춰 우선순위를 함께 정하면 좋겠습니다.
