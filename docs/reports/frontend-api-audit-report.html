여행지 탐색 /explore연동완료핵심 흐름(목록·시군구·상세·장바구니) 완료. 키워드 검색·축제·숙박·주변 API는 백엔드에 있지만 UI가 없습니다.

여행 계획 /trips연동완료계획 CRUD·일정 배치·공개 전환 12개 모두 실 API. 메모는 로컬 전용(백엔드 필드 없음), 지도 탭은 준비 중, 내 계획에 달린 참견 보기가 없습니다.
로그인·회원가입·소셜연동완료이메일 인증·가입·로그인·재설정·카카오/구글 OAuth 완료. Apple은 미도입, 비밀번호 변경 API는 화면이 없습니다.
온보딩 /onboarding/*연동완료선호도 등록 완료. 등록 후 수정하는 화면이 없어 PUT은 함수만 존재합니다.
공통 Navbar·챗봇·플로팅 장바구니부분연동알림·챗봇·장바구니는 실 API. 프로필 메뉴의 /mypage 링크는 라우트가 없어 빈 화면으로 이동합니다.

기능 공백
  • 일정 항목 메모 — 로컬 state에만 저장, 새로고침하면 사라짐(백엔드 DTO에 memo 필드 없음)
  • 지도 탭 — "지도 보기는 준비 중이에요" 플레이스홀더
  • 내 계획에 달린 참견 보기 — Navbar 알림이 /trips로만 보내고, 계획 안에서 참견 목록·추천 장소 담기(/feedback/all, /recommendations/{id}/cart) UI가 없음. 읽음 처리는 소유자가 목록을 조회할 때 서버가 자동 수행하므로 이 화면이 있어야 알림 배지가 줄어듭니다
  • 여행 기록 작성 진입점 없음 — 다녀온 계획에서 기록(/trips/{id}/record)을 남길 방법이 없음
  • 저장한 여행 목록/해제(/saved-trips GET·DELETE) 없음 — 저장한 계획은 복사본으로만 목록에 섞여 보임

백엔드에 없어서 막힌 것

프론트가 이미 UI를 갖고 있거나 필요로 하는데, 현재 백엔드에 대응 API/필드가 없는 항목입니다.

#필요한 것막히는 프론트 기능제안
1사진 업로드 API (파일 → imageUrl)여행 기록 작성 전체(TripRecordRequest.photos[].imageUrl 필수)POST /api/uploads multipart 또는 presigned URL 발급. 응답에 imageUrl

3좋아요 엔티티 · 토글 API · likeCount피드 카드 하트 버튼, TOP5 좋아요 수POST/DELETE /api/trips/{id}/likes, FeedItemResponse.likeCount·likedByMe. 도입하지 않을 거면 확정해 주시면 하트를 제거하고 저장 수로 통일
4피드 필터 파라미터피드 지역·유형 필터가 클라이언트 50건 안에서만 동작GET /feed?region=&type=PLAN|RECORD&keyword=, 인기 지역 집계 GET /feed/regions

우선순위 작업 목록

프론트에서 바로 할 수 있는 것부터, 백엔드 선행이 필요한 것 순으로 묶었습니다.

  1. HIGH여행자 피드 목업 걷어내기
    MOCK_FEED_ITEMS·MOCK_GALLERY_ITEMS 병합 제거, GET /feed 페이지네이션(page/size) + 스켈레톤·빈 상태. TOP5는 sort=popular&size=5 + saveCount(북마크 아이콘)으로 교체. data/feed.js는 삭제 가능해집니다.
  2. HIGH피드 상세 저장 버튼 · 카드 북마크를 saveTrip에 연결
    ParticipateSection의 "내 여행으로 담기/담았어요" 패턴을 그대로 재사용. 비로그인은 /login 유도, 성공 시 saveCount 낙관 증가.
  3. HIGH마이페이지 라우트 신설 (/mypage)
    현재 깨진 링크 수정. 내 정보(getMe), 비밀번호 변경(PATCH /auth/password), 선호도 수정(PUT /preferences), 저장한 여행(GET·DELETE /saved-trips), 받은 참견(/feedback/received). 미연동 5개가 한 번에 정리됩니다.
  4. HIGH여행 기록 작성 연동 (백엔드 사진 업로드 선행)
    RecordUploadModal 계획 선택을 getMyTrips로, 제출을 업로드 → POST /trips/{id}/record로. 여행 계획 화면에도 "기록 남기기" 진입점 추가. 업로드 API 확정 전에는 계획 선택·검증까지만 먼저 연결 가능.
  5. MID여행 계획에 "받은 참견" 패널
    GET /trips/{id}/feedback/all 목록, 추천 장소 카트 담기, 참견 삭제. Navbar 알림 항목은 /trips?open=<tripId>로 딥링크해 해당 계획을 열고 읽음 처리가 자연히 일어나게.
  6. MID참견 작성 확장 (일차·아이템 단위 + 추천 장소)
    createFeedback에 tripDayId/tripItemId/recommendations 전달. DayCard 클릭으로 대상 일차 지정, 장바구니에서 추천 장소 첨부.
  7. MID피드 액션바 실동작
    댓글 → 참견 목록/작성 드로어, 공유 → 링크 복사/navigator.share. 좋아요는 백엔드 결정 전까지 숨김.
  8. MID탐색 키워드 검색 + 축제/숙박 전용 탭
    검색 입력 → getTourContents({keyword}). 축제는 /tour/festivals(이달 기간), 숙박은 /tour/stays로 교체해 기간·전용 정보 표시.
  9. MID일정 메모 저장 (백엔드 memo 필드 선행) · 지도 탭
    memo 필드가 추가되면 updateTripItemTime와 같은 PATCH로 저장. 지도 탭은 항목 좌표로 마커 + /tour/contents/nearby 주변 추천.
  10. LOW정리 작업
    미사용 레거시 컴포넌트 9개 삭제, FEED_REGIONS는 백엔드 지역 필터 도입 시 제거, Apple 로그인은 등록 후 버튼 활성화.

백엔드 요청 목록

프론트 연동을 진행하기 위해 백엔드 팀에 요청할 항목입니다. 위 "백엔드에 없어서 막힌 것"의 실행 버전입니다.

  • 사진 업로드 API — 여행 기록 작성의 유일한 차단 요소. multipart 업로드 또는 presigned URL 중 방식 확정 요청.
  • TripItem memo 필드 — Add/Update 요청·응답 DTO에 memo 추가. 프론트는 이미 편집 UI가 있어 필드만 생기면 즉시 저장 연동 가능.
  • 좋아요 도입 여부 확정 — 도입 시 토글 API + likeCount/likedByMe. 미도입이면 프론트에서 하트를 제거하고 저장 수로 통일.
  • 피드 서버 필터 — region, type, keyword 파라미터와 인기 지역 집계. 현재 클라이언트 필터는 50건 한도 안에서만 동작.
  • 프로필 조회·수정 — 닉네임·프로필 이미지. 피드 카드 아바타와 마이페이지에 필요.
  • FeedItemResponse에 recordId — 기록 카드에서 수정/삭제 진입용.
  • (이전 보고서 이월) 추천 매칭용 시드 데이터 확충, 로컬 개발용 CORS Origin 패턴, Apple OAuth 등록.
